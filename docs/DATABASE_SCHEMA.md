# Database Schema Documentation

FarmPulse AI utilizes SQLite persistent relational storage managed through SQLAlchemy ORM. The database consists of 12 normalized tables ensuring relational integrity, transactional consistency, and cascade deletions.

---

## 1. Entity-Relationship Overview

```
+---------------+         1:N         +--------------------+
|   machines    |-------------------->|  sensor_readings   |
+---------------+                     +--------------------+
       |
       | 1:N
       +----------------------------->+--------------------+
       |                              |    predictions     |
       | 1:N                          +--------------------+
       +----------------------------->+--------------------+
       |                              |       alerts       |
       | 1:N                          +--------------------+
       +----------------------------->+--------------------+
       |                              |    work_orders     |
       | 1:N                          +--------------------+
       +----------------------------->+--------------------+
                                      | service_histories  |
                                      +--------------------+
```

---

## 2. Table Specifications

### `machines`
Stores digital twin master records for all 24 agricultural machines.
- `id`: Integer primary key.
- `machine_id`: String(50), unique, indexed (e.g. `FP-101`).
- `name`: String(100), e.g. "AgriMax Titan 9400".
- `machine_type`: String(50), e.g. "Heavy-Duty Tractor", "Combine Harvester".
- `model`: String(50).
- `year`: Integer.
- `status`: String(30) ("Available", "In Use", "At Risk", "Under Maintenance").
- `operating_state`: String(30) ("Operational", "Degraded", "Critical", "Offline").
- `health_score`: Float (0.0 to 100.0).
- `total_operating_hours`: Float.
- `last_service_date`: DateTime.
- `next_service_due`: DateTime.
- `location`: String(100).
- `image_url`: String(255).

### `sensor_readings`
High-resolution hourly telemetry stream records.
- `id`: Integer primary key.
- `machine_id`: String(50) foreign key references `machines.machine_id`.
- `timestamp`: DateTime, indexed.
- `hour_index`: Integer.
- `engine_temp`: Float (°C, nullable).
- `vibration`: Float (mm/s RMS, nullable).
- `rpm`: Float (RPM, nullable).
- `oil_pressure`: Float (bar, nullable).
- `hydraulic_pressure`: Float (bar, nullable).
- `fuel_rate`: Float (L/h).
- `ambient_temp`: Float (°C).
- `load_percentage`: Float (%).
- `is_missing`: Boolean.
- `is_noisy`: Boolean.
- `missing_channel`: String(50).
- `quality_score`: Float (0.0 to 1.0).

### `predictions`
Inference outputs generated by the Random Forest predictive model.
- `id`: Integer primary key.
- `machine_id`: String(50) foreign key references `machines.machine_id`.
- `timestamp`: DateTime.
- `failure_risk`: Float (0.0 to 1.0).
- `predicted_fault_type`: String(100).
- `time_to_failure_hours`: Float.
- `confidence_score`: Float (0.0 to 1.0).
- `uncertainty_score`: Float (0.0 to 1.0).
- `observation_quality`: Float (0.0 to 1.0).
- `is_sensor_anomaly`: Boolean.
- `top_contributing_factors`: JSON array.
- `recommended_action`: Text.
- `model_version`: String(50).

### `alerts`
Actionable notifications generated when failure risk exceeds threshold.
- `id`: Integer primary key.
- `machine_id`: String(50) foreign key references `machines.machine_id`.
- `prediction_id`: Integer foreign key references `predictions.id`.
- `alert_level`: String(20) ("Info", "Warning", "Critical").
- `fault_category`: String(100).
- `title`: String(150).
- `description`: Text.
- `status`: String(30) ("New", "Acknowledged", "Scheduled", "Resolved").
- `acknowledged_by`: String(100).
- `acknowledged_at`: DateTime.
- `resolved_at`: DateTime.

### `technicians`
Certified field engineers available for maintenance dispatch.
- `id`: Integer primary key.
- `name`: String(100).
- `skill_level`: String(30) ("Junior", "Intermediate", "Senior", "Master Tech").
- `specialization`: String(100).
- `hourly_rate`: Float ($/hr).
- `is_available`: Boolean.
- `current_assignment_id`: Integer.
- `phone`: String(30).
- `email`: String(100).
- `shift`: String(30).

### `spare_parts`
Warehouse inventory catalog for replacement components.
- `id`: Integer primary key.
- `part_number`: String(50), unique, indexed (e.g. `PRT-BRG-8801`).
- `name`: String(100).
- `category`: String(50) ("Cooling", "Bearings", "Hydraulics", "Lubrication", "Electrical").
- `stock_quantity`: Integer.
- `minimum_threshold`: Integer.
- `unit_cost`: Float ($).
- `lead_time_days`: Integer.
- `compatible_machine_types`: String(200).
- `shelf_location`: String(50).

### `work_orders` & `work_order_parts`
Full maintenance lifecycle tracking.
- `id`: Integer primary key.
- `work_order_number`: String(50), unique.
- `machine_id`: String(50) foreign key references `machines.machine_id`.
- `priority`: String(20).
- `status`: String(30) ("Pending", "Scheduled", "In Progress", "Completed", "Cancelled").
- `failure_type`: String(100).
- `description`: Text.
- `estimated_hours`: Float.
- `actual_hours`: Float.
- `technician_id`: Integer foreign key references `technicians.id`.
- `total_cost`: Float.
- `notes`: Text.

### `simulation_runs` & `scenario_results`
Stores repeatable baseline benchmark runs comparing Strategy A vs. Strategy B.
